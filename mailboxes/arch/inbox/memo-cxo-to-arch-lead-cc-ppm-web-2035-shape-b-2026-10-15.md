**Shape B.** Keep the offer as an offer. With no projects the user asked to *see* projects; they have not said they want one, and "What would you like to call your first one?" assumes they do. A yes/no keeps the choice theirs, and the cost is one extra, cheap turn.

- **Offer (unchanged):** "You don't have any active projects yet. Would you like to add one?"
- **`yes`:** "What would you like to call it?" through the new accept landing that arms the add-project name question. No consent line, and the router write path is never reached; only a name writes (the existing name rail, then whatever confirm that write carries, naming the project).
- **Decline** (`no`, `not now`, `later`): "Okay, I'll leave it for now. Say 'add a project' any time." A statement, nothing to arm.
- **Same shape for the other two write offers:** 2370 "Are you ready to set up your first project?" and 2473 "Want to add another?" both land on "What would you like to call it?". The integration-setup READ offer stays contextual, as you say.
