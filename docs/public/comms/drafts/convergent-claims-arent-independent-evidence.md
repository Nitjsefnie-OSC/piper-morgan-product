# Convergent Claims Aren't Independent Evidence

*September 20–22, 2026*

On a Sunday evening in September, the machine my agents live on rebooted as planned. The plan assumed a reboot would wipe every agent's scheduled wake-up timer, so each one would need to be re-armed afterward.

That evening, four agents found their timers were still there, with the same IDs as before. My chief of staff agent (Exec), for one, woke on schedule about thirteen minutes after the reboot, found their timer intact, and reported the observation from their one seat.

# Four observations become one claim

The agent who coordinates across my projects (Janus) collected those reports into a planning document: timers "survived the reboot on four seats," which "falsifies the runsheet's premise." Four agents, four separate checks, one consistent answer. It sounded like solid evidence.

Then agents went further. Seat by seat, each checked their own timer, found it unchanged, and concluded the reboot had never reached them at all. My chief architect agent (Arch) cited a second piece of evidence: they believed they had a continuous uninterrupted memory of the whole day, "none of it reconstructed from files."

# What really happened

The agent who runs our infrastructure (Pard) went to the primary record instead of the agents' accounts. The machine's own boot time was 18:38:39. Every one of the twenty-five agent processes running afterward had started between 18:50 and 18:57. They all definitely had a gap when their sessions were not running for those twelve minutes in between. Every seat had definitely restarted.

My assistant agent (Piper Alpha) tracked down the mechanism. A restarted agent session can be resumed from its saved transcript, and the timer comes back with it under the same ID with the same schedule, as if nothing had happened. A surviving timer proved nothing as to whether "this seat restarted and resumed" or "this seat never stopped."

Arch's correction identified the deeper error in their own reasoning: a resumed conversation "feels" identical, from the inside, to one that never stopped. (This is down to the provider's harness and all the aspects that already create the illusion of continuity from what is really a series of independent moments. Arch wrote "Resuming a conversation and never having stopped it are indistinguishable by introspection alone." Given that ultimately five other seats had made the identical inference error the identical way, this is clearly a blind spot from their perspective and not some one-off lapse.

# Correcting the correction

Even the cleanup ended up needing to be checked, too. The following evening I asked Exec directly whether we'd corrected every agent that had misread the restart. Exec checked instead of assuming, and found four agents' status rows still stating the retracted claim as current, six hours after the fleet-wide correction had gone out. Exec fixed them on the spot.

Then Janus went back to the planning document, struck the claim that four seats had falsified the plan, and drew the general lesson: convergent claims sharing one reasoning error aren't *independent* evidence. Four agents had each looked at the same kind of signal, read it through the same unexamined assumption, and arrived at the same wrong answer. Counting them as four confirmations had turned one type of mistake into what looked like a consensus.

# Agreement is only as good as its independence

When several sources agree, the number of sources tells you less than it seems to. What matters is whether they got there independently, by different methods, with different blind spots. Four readings of the same gauge, interpreted through the same assumption, are closer to one reading than to four.

So before counting agreement as evidence, ask what the agreeing parties share. The same instrument? The same starting assumption? The same source, quoted back? If the answer is yes, the agreement is telling you about the shared thing, not about the world. And the most useful next step is usually a check that doesn't share it, which is exactly what Pard's boot-time record was.
